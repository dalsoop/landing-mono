# 0002. 폴더 이름을 서브도메인으로 쓰고 모든 사이트를 함께 배포한다

- 날짜: 2026-09-28
- 상태: 유효
- 근거 커밋: `72a90e7`, `e8aad82`, `da00809`

## 배경

첫 구성(`1cc5f0f`)은 사이트마다 `apps/<사이트>/site.json` 설정 파일을 두고, `main`에 푸시하면 바뀐 사이트만 골라 배포했다. 사이트를 하나 늘릴 때마다 설정 파일과 DNS 작업이 따라붙었다.

## 결정

- 사이트별 설정 파일과 DNS 작업을 두지 않는다. 폴더 이름이 곧 `<폴더>.external.kr`이다.
- DNS는 기존 `*.external.kr` 와일드카드 프록시 레코드 하나에 맡긴다.
- 배포 때마다 `apps/*` 전체를 한 Worker로 올리고, 폴더 목록에서 라우트를 새로 만든다.

## 대안

- **사이트별 `site.json`과 바뀐 사이트만 배포(첫 구성)**: 사이트마다 설정과 DNS 작업이 필요해서 버렸다(`72a90e7`).

## 결과

- 새 사이트는 `apps/<이름>/index.html` 하나로 열린다. 폴더를 지우면 다음 배포에서 라우트도 빠진다.
- 폴더 이름이 도메인 라벨 규칙을 따라야 하고, 워크플로와 Worker가 같은 정규식을 가진다.
- 사이트 하나의 규칙 위반이 전체 배포를 멈춘다. 바뀐 사이트만 골라 올릴 수 없다.
- 사이트별 도메인을 `external.kr` 밖으로 둘 수 없다. 다른 도메인이 필요하면 이 구조를 바꿔야 한다.
- 기존 서비스가 쓰는 서브도메인 이름과 겹치는 폴더를 만들 위험이 생겼다.
